# 微博点赞与转发结算设计

## 目标

让微博卡片的点赞和转发从纯视觉状态变成真实游戏行为。结算由帖子 `sceneId`、发帖者立场和当前账号共同决定。

## 核心规则

- 互动状态由 Zustand 持久化，按“当前账号 + 帖子 ID”隔离。
- 点赞和转发分别只在首次开启时结算一次。
- 取消点赞或转发只改变按钮状态，不撤销已经发生的数值、热搜和反馈。
- 取消后重新开启不重复结算，防止刷数值。
- 小号互动不直接改变艺人数值或热搜，只给出低曝光反馈。
- 艺人大号与自己的帖子互动不产生数值影响。
- 艺人大号与外部帖子互动时，转发的影响强于点赞。

## 结算模型

基础影响先由发帖者立场决定：

| 立场 | 点赞 | 转发 |
| --- | --- | --- |
| supportive | 粉丝忠诚 +1 | 粉丝忠诚 +2、商业价值 +1 |
| procedural | 粉丝忠诚 +1 | 粉丝忠诚 +1 |
| neutral | 无数值变化 | 舆论风险 +1 |
| skeptical | 舆论风险 +2、粉丝忠诚 -1 | 舆论风险 +4、粉丝忠诚 -2 |
| hostile | 舆论风险 +4、粉丝忠诚 -2 | 舆论风险 +7、粉丝忠诚 -4、商业价值 -1 |

场景在基础影响上追加修正：

- CP 讨论：艺人大号点赞或转发会增加恋情猜测，额外增加舆论风险；转发进入热搜。
- 私生活路透、危机围观：视为主动放大敏感信息，额外增加舆论风险并进入热搜。
- 粉圈冲突、媒体黑稿、黑对家、反串：视为艺人公开下场，显著增加舆论风险；转发必进热搜。
- 品牌销量、应援活动、作品宣传：支持性互动可增加商业价值或粉丝忠诚。

所有数值仍通过现有 `applyStatChanges()` 处理，保留艺人特质和 0-100 边界。

## 数据结构

新增持久化 `weiboInteractions`：

```ts
Record<string, {
  liked: boolean;
  reposted: boolean;
  likeSettled: boolean;
  repostSettled: boolean;
}>
```

键格式为 `${account}:${postId}`，确保小号和艺人大号互不串状态。

`WeiboCard` 接收作者账号和发帖立场，只负责展示与派发操作。Store action 原子完成切换、首次结算、热搜插入和结果返回。

## 反馈

- 首次有效互动：显示具体后果，例如“艺人大号点赞了争议帖，舆论风险上升”。
- 取消互动：提示“截图可能已经留下，此前影响不会撤销”。
- 重新开启：提示“已重新点赞/转发，不会重复结算”。
- 小号互动或自己给自己互动：说明没有公开影响。

## 兼容与测试

- 旧存档缺少 `weiboInteractions` 时按空对象处理。
- 单测覆盖账号隔离、首次结算、取消不回滚、重新开启不重复结算、风险热搜和小号零影响。
- 完成后运行完整 Vitest、TypeScript、生产构建和 `git diff --check`。
